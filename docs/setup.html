Set up Vaulter from scratch

Plan on an afternoon. You need a super-admin with Vault privileges, a new Google Sheet and the code from github.com/OPS-JMellor/Vaulter. Nothing runs anywhere but Apps Script, and the whole thing runs as the admin who sets it up, so sign in as that account for every step.

BEFORE YOU START

  • Google Workspace for Education with Gemini turned on for the student organizational units you want to watch.
  • Those students hold a Google Vault license. Vault is where Gemini activity is retained; without it, every export comes back empty.
  • A super-admin account with Vault privileges (manage matters, manage exports) and Admin SDK read access. Everything runs as this account.
  • Optional: a Gemini API key from Google AI Studio for the triage step. Without it, matches are still flagged, just without an AI verdict.

STEP 1MAKE THE SHEET AND THE SCRIPT

  1. Create a Google Sheet and name it Vaulter.
  2. Open Extensions, then Apps Script. In Project Settings tick "Show appsscript.json manifest file in editor".
  3. Copy every file from the repo's apps-script/src folder into the script with the same names, replacing the default Code.gs: Config.js, Auth.js, VaultImport.js, Scanner.js, Alerts.js, Scheduler.js, SheetSetup.js, WebApp.js, index.html, Demo.html and appsscript.json. The manifest carries the OAuth scopes, so it must be copied too.
  4. Prefer the command line? Install clasp (npm install -g @google/clasp), run clasp login, copy apps-script/.clasp.json.example to .clasp.json with your script ID (Project Settings), and run clasp push from that folder.

The script finds its own Sheet because it is bound to it. Nothing in the code needs editing for your district.

STEP 2CREATE THE TABS

  1. In the editor, pick setupSheets from the function list and press Run.
  2. Approve the permissions prompt. It asks for Vault, Admin SDK read, Sheets, Gmail send and triggers, all on your own account.
  3. Eight tabs appear with headers and defaults: Vault_Data, Flagged, Alerts_Config, App_Config, Setup, Run_Log, AI_Filtered and Access_List.

Then add the Gemini key: Project Settings, Script properties, add GEMINI_API_KEY with the key as its value. Every setting in the table can also be changed later from the dashboard's Settings and Access pages.

STEP 4PUBLISH THE DASHBOARD

  1. Deploy, then New deployment. Type: Web app. Execute as: Me. Who has access: Anyone within your domain. Deploy and copy the URL.
  2. Add a script property DASHBOARD_URL with that URL so the Sheet's Vaulter menu opens it.
  3. Open the URL. Your account is on Access_List, so it loads. Add other reviewers on the Access page. The Demo switch in the header shows fictional sample data for walkthroughs.
  4. For every later code change: Deploy, Manage deployments, edit the existing deployment and pick New version. The URL stays the same. A brand-new deployment makes a new URL.

STEP 5SCHEDULE AND FIRST RUN

  1. Run installTrigger once from the editor. It creates the scheduled runPipeline trigger at the configured time. Saving settings in the dashboard reinstalls it too.
  2. Click Run import now. The first run creates a Vault matter named "Vaulter — Gemini Activity Imports", queues one export per OU, and installs a five-minute checker trigger that collects each export when Vault finishes it, usually within the hour.
  3. Watch Run_Log and the readout strip at the top of the dashboard. When an export lands, matches appear in Flagged and the queue, and the alert email goes out on that run or the next.

IF SOMETHING IS OFF

  • Settings shows no OUs, or Run_Log says it could not resolve an OU: the account lacks Admin SDK read, or the OU path in Setup is misspelled.
  • Run_Log says Vault POST failed with 403: the account lacks Vault privileges, or Gemini activity is not retained in Vault for those users.
  • Exports never finish: open Vault in the Admin console, find the matter and its Exports list; failed exports show there. Run clearPendingExports from the editor to reset the queue.
  • No email: check Alert Recipients and the Run_Log Alerted column. Apps Script caps daily mail per account.
  • No AI verdicts: GEMINI_API_KEY is missing, or the key's project has the Generative Language API turned off. Flags still appear.
  • A run stops at six minutes: that is the Apps Script execution cap, which is why exports are collected by the checker trigger instead of in the run itself.
