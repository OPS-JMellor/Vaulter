Set up Vaulter from scratch

Five stages, about an afternoon. You need a super-admin with Vault privileges, a new Google Sheet and the code from GitHub. Everything runs as the admin who sets it up, so sign in as that account for every step.

1Sheet and script20 min · copy 11 files in 2Create the tabs5 min · run one function 3Configure15 min · four tabs, one key 4Publish the dashboard10 min · one deployment 5Schedule and first run10 min, then wait for Vault

BEFORE YOU STARTWHAT HAS TO BE TRUE ALREADY

  • Google Workspace for Education with Gemini turned on for the student organizational units you want to watch.
  • Vault licenses for those students. Vault is where Gemini activity is retained; without it, every export comes back empty.
  • A super-admin account with Vault privileges (manage matters, manage exports) and Admin SDK read. Everything runs as this account.
  • Optional: a Gemini API key from Google AI Studio for the triage step. Without it, matches are still flagged, just without an AI verdict.

STAGE 1ABOUT 20 MINUTES

1

Make the Sheet and the script

The Sheet holds the data; the script bound to it is Vaulter.

  1. Create a new Google Sheet and name it Vaulter.
  2. Open the script editor: Extensions›Apps Script
  3. Show the manifest: Project Settings›Show "appsscript.json" manifest file in editor
  4. Add each file from the repo's apps-script/src folder with the same name, and delete the default Code.gs. Use the + next to Files; pick Script for .js files and HTML for .html files. Replace the manifest's contents too, since it carries the OAuth scopes.
Config.jsAuth.jsVaultImport.jsScanner.jsAlerts.jsScheduler.jsSheetSetup.jsWebApp.jsindex.htmlDemo.htmlappsscript.json
Prefer the command line? npm install -g @google/clasp, clasp login, copy apps-script/.clasp.json.example to .clasp.json with your script ID from Project Settings, then clasp push from the apps-script folder.
Done when the Files list shows the eleven names above and nothing else. Nothing in the code needs editing for your district: the script finds its own Sheet because it is bound to it.

STAGE 2ABOUT 5 MINUTES

2

Create the tabs

One function builds every tab with its headers and defaults.

  1. In the editor toolbar, pick setupSheets from the function dropdown and press Run.
  2. Approve the permissions prompt. It asks for Vault, Admin SDK read, Sheets, Gmail send and triggers, all on your own account. Choose your admin account and allow.
  3. Switch back to the Sheet. Eight tabs are now there:
YOUR SHEET
Vault_DataFlaggedAlerts_ConfigApp_ConfigSetupRun_LogAI_FilteredAccess_List
Done when the eight tabs exist and Alerts_Config shows six default categories. A Vaulter menu also appears in the Sheet's menu bar the next time you open it.

STAGE 4ABOUT 10 MINUTES

4

Publish the dashboard

One web app deployment. Its URL is what reviewers bookmark, so keep it.

  1. In the editor: Deploy›New deployment›Select type: Web app
  2. Fill the dialog exactly like this, then press Deploy and copy the URL:
NEW DEPLOYMENT · WEB APP
DescriptionVaulter dashboard Execute asMe (your admin account) Who has accessAnyone within your domain
  1. Paste the URL into the DASHBOARD_URL script property so the Sheet's Vaulter menu opens it.
  2. Open the URL. Your account is on Access_List, so it loads. Add other reviewers on the Access page. The Demo switch in the header shows fictional sample data for walkthroughs.
Every later code change: Deploy›Manage deployments›Edit›Version: New version keeps the same URL. A brand-new deployment makes a new URL and breaks bookmarks.
Done when the dashboard opens with an empty queue, the readout strip says PIPELINE ACTIVE, and the Settings page lists your organizational units.

STAGE 510 MINUTES, THEN WAIT FOR VAULT

5

Schedule and first run

Install the trigger, kick off an import, watch the first flags arrive.

  1. In the editor, run installTrigger once. It creates the scheduled runPipeline trigger at the configured time. Saving settings in the dashboard reinstalls it too.
  2. In the dashboard, press Run import now. The first run creates a Vault matter named "Vaulter — Gemini Activity Imports", queues one export per OU, and installs a five-minute checker trigger that collects each export when Vault finishes it, usually within the hour.
  3. Watch the readout strip. It shows exports processing, then the last run. The Run_Log table on the Settings page shows every run with counts and any error.
Done when Run_Log shows a SUCCESS row, matches appear in the queue, and the alert recipients get an email on that run or the next. From here the schedule runs itself.

IF SOMETHING IS OFFSYMPTOM · LIKELY CAUSE · FIX

You seeLikely causeFix
Settings shows no OUs, or Run_Log says it could not resolve an OUThe account lacks Admin SDK read, or the OU path in Setup is misspelledCheck the path against the Admin console; it starts with a slash and matches case
Run_Log: Vault POST failed (403)The account lacks Vault privileges, or Gemini activity is not retained in Vault for those usersGrant Vault privileges in the Admin console; confirm Gemini is covered by Vault for the OU
Exports never finishVault failed the exportOpen Vault, find the matter and its Exports list. Run clearPendingExports from the editor to reset the queue, then Run import now again
No alert emailNo recipients, or the daily mail quotaCheck App_Config Alert Recipients and the Alerted column in Run_Log
No AI verdictsGEMINI_API_KEY missing, or its project has the Generative Language API offAdd the property; flags still appear without it
A run stops at six minutesThe Apps Script execution capExpected. Exports are collected by the checker trigger instead of in the run
Access Denied on the dashboardThe signed-in account is not on Access_ListAdd it on the Access_List tab, or have an Admin add it on the Access page
